## Findings, ordered by priority

### P0: Classification writes can duplicate amounts and lose prior decisions

`TaxClassificationService.classify()` always inserts a new row. Repeating the
same classification for a synthetic 12,345-cent rental expense produced a
24,690-cent deductible total. Aggregate allocation shares are not enforced.

`split()` commits deletion of the previous allocation before validating every
replacement part, then commits each part individually. A second part lacking
required authority raised an error after the original decision was erased and
the first 5,000-basis-point part persisted. Its computed allocation became zero.

Fix: validate every part before mutations; replace/revise the classification in
one transaction, retain review history, enforce complete shares and amount
consistency, and make replay behavior explicit. Add repeated-action and failed
replacement regression tests.

### P0: Rental totals bypass evidence verification and scope checks

`ReconciliationService.rental_totals()` sums classification amounts without
requiring that the referenced expense is VERIFIED or checking its current
source/amount. A PROPOSED synthetic expense entered a deductible total.
Corrected/superseded expenses can retain active classifications for the same
reason. Classification writes also succeeded after locking the workspace.

Fix: require existing subjects/properties in the selected workspace, enforce
locked state, distinguish verification of a source amount from approval of tax
treatment, and exclude stale/unverified evidence from approved totals. Validate
the classification amount against its actual source rather than caller input.

### P0: Missing classifications are omitted without an unresolved warning

`bank_flow_totals()` iterates classification records rather than all selected
tax-year transactions. An explicit account containing an unclassified
50,000-cent transaction returned no totals and unresolved_count=0.

Fix: define the account/property scope explicitly and account for every relevant
source row as approved, excluded or unresolved. Apply the same completeness
check to rental records. Keep rejected/superseded history separate from pending
work, so resolved corrections do not become permanent unresolved items.

### P0: Document corrections leave persisted runs marked CURRENT

`TaxWorkspaceService._invalidate_downstream()` invalidates comparison items and
packets, but omits `ReconciliationRun`. After correcting a document containing a
verified 1,000-cent field, the newly computed total became zero while its older
persisted run remained CURRENT. Classification writes have no run-invalidation
hook either.

Fix: use one evidence-change invalidation operation for fields, document
corrections, classification changes and ledger mutations. Include persisted runs,
comparison items and packets atomically. Recomputing after a transaction edit
must also refresh or invalidate classification amounts rather than reuse old
copied amounts.

### P1: Original documents are retained but not exposed in the review UI

The inspector displays extracted text only; it has no PDF/image preview or
download action. The verification queue displays snippets and allows approval
without exposing the cited original page. This is especially limiting for
scanned documents and scrambled columns.

Fix: expose the hash-verified original locally, show the cited page beside the
field under review, and label extracted text as a locating aid. Preserve per-page
statuses in intake DTOs and the UI: the current tuple/dictionary adapter discards
most structured status information and `preview_for_page()` is not used by the
UI. Avoid re-extracting every document on every widget rerun.

### P1: PDF execution limits are observational, not interruptible

`pdf_text.py` checks elapsed time after `extract_text()` returns and truncates
the output after its allocation. Initial parsing/page-tree traversal is outside
the measured budget. A synthetic 100ms extraction with a 2ms total budget still
took 103ms before returning TRUNCATED. A hung call or large decompression can
therefore block intake despite the bounded-extraction claim.

Fix: perform parsing/extraction in a worker process with enforced wall-time and
appropriate memory limits, preserve originals/manual entry after failures, and
test worker termination rather than merely status flags. This is still a good
use of pypdf; choosing another library does not itself solve execution limits.

### P1: Intake summary and checklist can imply more certainty than they provide

The “Verified Total” KPI sums heterogeneous fields such as proceeds, basis,
interest and expenses. This number has no coherent tax meaning. The inventory
marks a category PRESENT after one file, even if another broker/property is
missing. It hardcodes a 2025 checklist while permitting other tax years, and
marks mortgage/property forms required regardless of actual circumstances.

Fix: show verified item counts and totals grouped by explicit field/type;
configure expected documents by broker/property/year and applicability. Provide
residency/filing-status entry before jurisdiction-dependent guidance. Make the
reviewer's identity explicit rather than recording every approval as “Reviewer”.
